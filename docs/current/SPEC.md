## 1. 기능 요구사항

### 1.1 리소스와 탭의 일반화

#### FR-1. 리소스 종류는 확장 가능한 문자열이다

* 내용: 탭이 나타내는 대상의 종류를 껍데기에 고정된 목록으로 두지 않는다. 앱이
  종류를 자유롭게 더할 수 있어야 하며, 껍데기는 그 값을 전달만 하고 의미를 해석하지
  않는다.
* 근거: D-3, `_archive\260905_file_tab_explorer_templates` D-4
* 판정 방법:
  * 껍데기 코드에서 종류 값을 열거한 목록이나 상수 집합이 0건인지 확인한다.
  * 시험이 껍데기에 없던 종류 문자열 하나를 등록했을 때, 껍데기 코드 수정 없이
    등록이 받아들여지는지 확인한다.

#### FR-2. 탭의 정체성과 리소스 주소를 분리한다

* 내용: 열린 탭 인스턴스를 식별하는 값과, 그 탭이 가리키는 대상의 주소는 서로 다른
  값이어야 한다. 같은 대상을 다시 열 때 기존 탭을 쓸지 새 탭을 만들지는 종류별
  중복 정책(FR-8)이 정하며, 껍데기가 미리 정하지 않는다.
* 근거: D-3, `_archive\260905_file_tab_explorer_templates` D-5
* 판정 방법:
  * 같은 대상 주소로 두 번 여는 시험에서, 중복 정책이 "기존 탭 사용"이면 탭 수가
    1이고 "항상 새 탭"이면 2가 되는지 각각 확인한다.
  * 후자에서 두 탭의 식별값이 서로 다른지 확인한다.
  * 껍데기 코드가 대상 주소를 탭 식별값으로 그대로 쓰는 곳이 0건인지 확인한다.

#### FR-3. 리소스는 직렬화 가능한 설명만 담는다

* 내용: 탭이 안고 있는 대상 설명에는 보기가 대상을 다시 찾는 데 필요한 데이터만
  담아야 한다. 프로세스 객체 · 네이티브 핸들 · 화면 객체 같은 실행 중 객체를 담지
  않는다. 실행 중 상태가 필요한 보기는 탭 식별값을 키로 하는 별도 보관 자리를 쓴다.
* 근거: D-4, D-5, `_archive\260905_file_tab_explorer_templates` D-6
* 판정 방법:
  * 열린 탭 전부의 대상 설명을 문자열로 바꿨다가 되돌리는 시험이 손실 없이
    통과하는지 확인한다.
  * 그 시험을 두 갈래에서 각각 수행해 같은 결과가 나오는지 확인한다.
  * 오래 사는 상태를 갖는 시험용 보기에서, 그 상태가 대상 설명이 아니라 별도 보관
    자리에 있는지 확인한다.

#### FR-4. 껍데기가 리소스 종류를 모른다

* 내용: 껍데기 코드에 특정 종류를 직접 비교하는 분기가 없어야 한다. 종류를 아는
  코드는 갈아끼우는 자리(1.2) 안에만 있다.
* 근거: D-3, `BRIEF.md` 5절 1번
* 판정 방법:
  * 껍데기 코드에서 종류 값과의 비교문을 검색해 0건인지 확인한다.
  * 껍데기 코드에서 `file` · `folder` · `terminal` 같은 종류 이름 문자열을 검색해
    0건인지 확인한다. 프리셋(FR-31)과 참조 보기(FR-34)는 껍데기가 아니므로 이
    검색의 대상이 아니다.

### 1.2 갈아끼우는 자리 다섯

#### FR-5. 트리 항목 자리

* 내용: 트리에 무엇을 표시할지 고르는 자리를 껍데기 밖에 둔다. 이 자리는 껍데기가
  읽어 온 한 단계의 항목 목록을 받아, 표시할 것만 골라 돌려준다. 아무것도 갈아끼우지
  않으면 받은 것을 그대로 표시한다.
* 근거: D-3
* 판정 방법:
  * 확장자 하나만 남기는 것을 끼웠을 때 트리에 그 확장자와 폴더만 남는지 확인한다.
  * 폴더만 남기는 것을 끼웠을 때 파일 행이 0건인지 확인한다.
  * 두 시험 모두에서 껍데기 코드의 변경 줄 수가 0인지 확인한다.

#### FR-6. 행 선택 매핑 자리

* 내용: 트리의 행을 골랐을 때 어떤 종류의 탭을 열지 정하는 자리를 껍데기 밖에 둔다.
  이 자리는 고른 행을 받아 열 대상(종류와 주소)을 돌려주거나, 열지 않음을 돌려준다.
* 근거: D-3
* 판정 방법:
  * 파일 행에서만 탭이 열리도록 끼웠을 때 폴더 행을 골라도 탭이 생기지 않는지
    확인한다.
  * 폴더 행에서만 탭이 열리도록 끼웠을 때 파일 행에서 탭이 생기지 않는지 확인한다.
  * 두 시험 모두에서 껍데기 코드의 변경 줄 수가 0인지 확인한다.

#### FR-7. 보기 제공자 자리

* 내용: 탭 안을 그리는 자리를 껍데기 밖에 둔다. 보기는 종류마다 등록되며, 껍데기는
  탭을 열 때 그 종류에 등록된 보기를 만들어 붙인다. 등록된 보기가 없는 종류는
  FR-35의 규약대로 알리고 앱은 계속 돌아야 한다.
* 근거: D-3, D-4
* 판정 방법:
  * 종류 둘에 서로 다른 보기를 등록했을 때, 각 탭에 해당 보기가 나타나는지 확인한다.
  * 등록되지 않은 종류로 탭을 여는 시험에서 앱이 멈추지 않고 알림이 남는지 확인한다.
  * 보기를 다른 것으로 바꿨을 때 껍데기 코드의 변경 줄 수가 0인지 확인한다.

#### FR-8. 중복 정책 자리

* 내용: 같은 대상을 다시 열 때 기존 탭을 쓸지 새 탭을 만들지 정하는 자리를 껍데기
  밖에 둔다. 이 자리는 상태를 갖지 않는 판정이며, 판정 범위(조각 안에서 볼지 패널
  안에서 볼지)도 이 자리가 정한다.
* 근거: D-3, D-4, D-7
* 판정 방법:
  * "같은 주소면 기존 탭"을 끼우고 같은 대상을 두 번 열어 탭 수가 1인지 확인한다.
  * "항상 새 탭"을 끼우고 같은 대상을 두 번 열어 탭 수가 2인지 확인한다.
  * 보기 영역을 가른 상태에서, 판정 범위를 조각으로 둔 것과 패널로 둔 것이 서로 다른
    결과를 내는지 확인한다.

#### FR-9. 여는 경로 자리

* 내용: 트리를 거치지 않고 탭을 여는 수단을 더할 수 있는 자리를 껍데기 밖에 둔다.
  이 자리로 연 탭은 트리를 거쳐 연 탭과 같은 규칙으로 다뤄져야 한다 — 중복 정책,
  미리보기와 고정, 닫기, 패널 이동이 모두 같다.
* 근거: D-3
* 판정 방법:
  * 버튼 하나를 더해 탭을 여는 시험에서, 껍데기 코드 변경 줄 수가 0인지 확인한다.
  * 그 탭에 대해 중복 정책 · 고정 · 닫기 · 반대쪽 패널 이동이 트리로 연 탭과 같게
    동작하는지 각각 확인한다.
  * 그 탭을 열 때 트리 커서가 움직이지 않는지 확인한다(FR-19).

#### FR-10. 다섯 자리만 갈아끼워 새 종류가 붙는다

* 내용: 껍데기가 알지 못하는 임의의 종류 하나를, 위 다섯 자리를 갈아끼우는 것만으로
  탭에서 열 수 있어야 한다.
* 근거: D-3, `BRIEF.md` 5절 2번
* 판정 방법:
  * 시험이 껍데기에 없던 종류 하나를 등록하고, 그 종류의 탭을 열어 보기가 화면에
    나타나는지 확인한다.
  * 그 시험에서 껍데기 코드의 변경 줄 수가 0인지 확인한다.
  * 그 탭에 대해 미리보기 · 고정 · 닫기 · 패널 이동이 모두 동작하는지 확인한다.

### 1.3 보기의 수명과 상태

#### FR-11. 보기는 수명주기를 갖는다

* 내용: 보기는 탭이 열릴 때 만들어지고, 활성화 · 비활성화 · 크기 변경을 통보받으며,
  탭이 닫힐 때 폐기된다. 보이지 않는 탭의 보기는 비활성 상태여야 한다.
* 근거: D-4
* 판정 방법:
  * 탭을 열고 · 전환하고 · 크기를 바꾸고 · 닫는 동안 각 통보가 정의된 순서로 한
    번씩 불리는지 확인한다.
  * 폐기 뒤에 그 보기가 화면을 고치려 하지 않는지 확인한다.
  * 탭 둘을 열고 하나를 활성으로 뒀을 때, 다른 하나가 비활성 상태인지 확인한다.

#### FR-12. 탭 수명 동안 보기 인스턴스가 유지된다

* 내용: 탭을 다른 탭으로 전환했다가 돌아오거나, 반대쪽 패널로 옮기거나, 껍데기가
  다시 그려도 보기 인스턴스가 다시 만들어지지 않아야 한다. 폐기는 탭을 닫을 때만
  일어난다.
* 근거: D-4, `BRIEF.md` 5절 3번
* 판정 방법:
  * 보기가 만들어질 때마다 세는 시험용 보기로, 탭 전환 · 패널 이동 · 껍데기 재렌더링
    각각을 열 번씩 반복한 뒤 생성 횟수가 1인지 확인한다.
  * 오래 사는 상태(카운터 등)를 가진 시험용 보기에서, 위 세 동작 뒤에도 그 값이
    남아 있는지 확인한다.
  * 탭을 닫았을 때만 폐기가 불리는지 확인한다.

#### FR-13. 세션 상태와 영속 상태를 나눈다

* 내용: 껍데기가 보관하는 보기 상태는 세션 안에서만 살아 있다. 탭 전환과 패널
  이동을 넘어 유지되지만, 앱을 다시 켜면 복원하지 않는다. 껍데기는 그 값을 해석하지
  않고 보관과 전달만 한다. 앱을 다시 켜도 남아야 하는 것은 보기가 자기 저장 구역에
  직접 담으며, 껍데기는 그 내용을 알지 않는다.
* 근거: D-5
* 판정 방법:
  * 시험용 보기가 맡긴 값이 탭 전환과 패널 이동 뒤에 그대로 돌아오는지 확인한다.
  * 앱을 다시 켰을 때 그 값이 복원되지 않는지 확인한다.
  * 껍데기 코드가 그 값의 내부를 읽거나 비교하는 곳이 0건인지 확인한다.
  * 보기가 자기 저장 구역에 담은 값은 다시 켠 뒤에도 남아 있는지 확인한다.

### 1.4 탐색기

이 절의 요구는 `explorer_templates` v0.1이 도달한 동작을 그대로 재현하는 것이다
(D-11). 판정 방법도 v0.1의 것을 따른다.

#### FR-14. 탐색기 머리글

* 내용: 머리글 왼쪽에 구역 이름 `EXPLORER`를 대문자로 두고, 오른쪽에 폴더 열기 ·
  새로 읽기 · 모두 접기 세 버튼만 둔다. 더보기 버튼을 두지 않는다.
* 근거: D-11, v0.1 FR-6
* 판정 방법:
  * 머리글에 세 버튼만 있고 더보기 버튼이 없는지 확인한다.
  * 폴더 열기가 루트 선택 창을 띄우고, 새로 읽기가 FR-17의 기억을 버리며, 모두 접기가
    메뉴의 같은 항목과 같은 동작을 하는지 각각 확인한다.

#### FR-15. 탐색기 폭 조절과 접기

* 내용: 탐색기와 보기 영역 사이의 손잡이를 끌어 폭을 바꿀 수 있어야 하고, 그때 보기
  영역의 폭이 함께 맞춰져야 한다. 탐색기를 접었을 때 보기 영역이 0폭으로 찌그러지지
  않아야 한다.
* 근거: D-11, v0.1 FR-7 · FR-5
* 판정 방법:
  * 손잡이를 끌어 폭이 바뀌고, 그동안 보기 영역의 내용이 잘리거나 겹치지 않는지
    확인한다.
  * 탐색기를 접은 상태에서 보기 영역의 폭이 0보다 큰지 확인한다.

#### FR-16. 트리의 겉모습과 정렬

* 내용: 다음을 모두 만족해야 한다.
  1. 행의 배경 강조가 탐색기 열의 좌우 끝까지 닿는다.
  2. 들여쓰기는 행 안쪽 여백으로 주며, 깊이당 8px이다.
  3. 접기 표시는 5×5 꺾쇠를 회전시켜 접힘 `>`과 펼침 `v` 두 상태로 나타낸다. 파일
     행에서는 자리만 두고 감춘다.
  4. 폴더 아이콘과 그 자식 행의 아이콘이 세로로 한 줄에 선다.
  5. 이름을 글자로만 표시하며 서식으로 해석하지 않는다.
  6. 선택된 행은 배경색만 바뀌고 글자색은 유지된다. 트리에 초점이 있을 때만 선택
     행에 1px 초점 테두리를 안쪽으로 그린다.
  7. 깊이마다 들여쓰기 안내선을 그린다.
  8. 폴더 이름은 본문색, 파일 이름은 흐린 색으로 두며 아이콘도 글자색을 따른다.
  9. 이름이 넘칠 때 접기 표시와 아이콘은 줄어들지 않고 이름만 말줄임한다.
* 근거: D-10, D-11, v0.1 FR-8
* 판정 방법:
  * 깊이 3 이상인 항목에 마우스를 올려 강조 영역의 왼쪽이 잘리지 않는지 확인한다.
  * 폴더를 펼치고 접으며 꺾쇠가 회전하는지 확인한다.
  * 같은 깊이의 폴더 행과 파일 행에서 아이콘의 x 좌표가 같은지 확인한다.
  * 이름에 `<` · `&` · `"`가 든 항목에서 이름이 글자 그대로 표시되는지 확인한다.
  * 이름에 `g` · `y` · `p`가 든 항목에서 글자 아래가 잘리지 않는지 확인한다.
  * 화면 폭을 넘는 긴 이름을 둔 fixture에서 들여쓰기 폭과 아이콘 x 좌표가 짧은 이름
    행과 같은지 확인한다.
  * 트리에서 초점을 뺐을 때 선택 행의 테두리가 사라지고 배경은 남는지 확인한다.

#### FR-17. 트리 지연 로딩과 기억

* 내용: 루트를 고르면 그 바로 아래 한 단계만 읽는다. 폴더를 펼칠 때 그 폴더 바로
  아래 한 단계를 읽는다. 한 번 읽은 폴더는 기억해 두어 접었다 다시 펼쳐도 다시 읽지
  않는다. 새로 읽기를 누르면 기억을 버리고 다시 읽되, 펼침 상태는 유지한다. 펼치는
  동안 자리표시를 보이며, 그동안에도 트리의 나머지를 조작할 수 있어야 한다.
* 근거: D-11, v0.1 FR-9
* 판정 방법:
  * 루트를 고른 직후, 펼치지 않은 폴더의 자식에 대한 읽기 요청이 0건인지 기록으로
    확인한다.
  * 폴더를 펼칠 때 읽기 요청이 한 번 일어나고, 접었다 다시 펼칠 때는 일어나지 않는지
    확인한다.
  * 새로 읽기 뒤 같은 폴더를 펼칠 때 읽기 요청이 다시 일어나는지 확인한다.
  * 폴더를 펼친 뒤 새로 읽기를 눌러도 펼침 상태가 남아 있는지 확인한다.

#### FR-18. 트리 탐색 키

* 내용: 다음 여섯 가지가 동작해야 한다.
  * `↑` `↓` — 펼쳐져 보이는 행을 기준으로 커서를 옮긴다. **탭은 바뀌지 않는다.**
  * `→` — 접힌 폴더면 펼치고, 이미 펼쳐졌으면 첫 자식으로 옮기며, 그 밖에는 아무 일도
    하지 않는다.
  * `←` — 펼쳐진 폴더면 접고, 접혔거나 자식이 없으면 부모로 옮긴다.
  * `Enter` — 열 수 있는 행이면 열고, 폴더면 접기와 펼치기를 오간다. 무엇이 열 수
    있는 행인지는 FR-6이 정한다.
  * `Home` — 보이는 행 중 맨 첫 행으로 커서를 옮긴다.
  * `End` — 보이는 행 중 맨 끝 행으로 커서를 옮긴다.
* 근거: D-11, v0.1 FR-10
* 판정 방법:
  * 여섯 키의 동작을 위 정의대로 각각 확인한다. 특히 접힌 폴더에서 `←`가 부모로
    올라가는지 확인한다.
  * 열 수 있는 행 위로 방향키를 열 번 지나가며 탭이 하나도 생기거나 바뀌지 않는지
    확인한다.
  * `Home` · `End`도 커서만 옮기고 탭을 바꾸지 않는지 확인한다.

#### FR-19. 트리 커서와 활성 탭의 분리

* 내용: 트리 커서와 활성 탭은 서로 다른 상태이며 어긋날 수 있어야 한다. 탭을 바꿔도
  트리 커서는 따라가지 않고, 트리가 지금 보는 대상을 자동으로 드러내지 않는다.
* 근거: D-11, v0.1 FR-30 · D-21
* 판정 방법:
  * `a`를 열고 방향키로 `b`까지 커서를 옮긴 뒤, 화면에 `a`가 남아 있고 트리 강조는
    `b`에 있는지 확인한다.
  * 탭을 여러 개 열고 서로 바꿔가며, 트리 커서가 움직이지 않고 접힌 폴더가 저절로
    펼쳐지지 않는지 확인한다.
  * 상태 표시줄의 경로가 트리 커서가 아니라 활성 탭의 대상을 가리키는지 확인한다.

#### FR-20. 루트 경계 강제

* 내용: 고른 루트 폴더 밖의 경로에는 접근하지 않아야 한다. 루트 밖을 가리키는 요청은
  거부하고 그 사실을 다른 오류와 구분되는 값으로 돌려줘야 한다. **이 검증은 연결
  계층이 수행한다** — 껍데기 화면이나 갈아끼우는 자리를 믿고 넘기지 않는다.
* 근거: D-11, `_archive\260905_folder_tab_explorer_templates` D-8, v0.1 FR-11
* 판정 방법:
  * 루트 밖 경로(`..`를 포함한 경로 · 절대 경로 · 루트 밖을 가리키는 심볼릭 링크)를
    넘기는 시험이 모두 거부되는지 확인한다.
  * 거부 사유가 없는 파일 등 다른 오류와 구분되는 값으로 돌아오는지 확인한다.
  * 위 시험을 껍데기를 거치지 않고 연결 계층에 직접 넣어도 거부되는지 확인한다.
  * 두 갈래 각각에서 위 셋을 확인한다.

### 1.5 껍데기의 화면과 사용성

이 절도 v0.1의 동작을 회귀 없이 유지하는 것이 목표다(`BRIEF.md` 5절 5번).

#### FR-21. 창과 다섯 구역

* 내용: 프레임리스 창으로 하고 그 자리를 메뉴 줄이 쓴다. 창 안은 메뉴 줄 · 세로 띠 ·
  탐색기 · 보기 영역 · 상태 표시줄 다섯 구역으로 나눈다. 창 제어(최소화 · 최대화
  토글 · 닫기)를 메뉴 줄 오른쪽에 둔다.
* 근거: D-11, v0.1 FR-1 · FR-2
* 판정 방법:
  * 다섯 구역이 모두 있고 겹치지 않는지 확인한다.
  * 최대화 토글이 창 상태를 번갈아 바꾸고, 창 밖에서 최대화됐을 때 버튼 표시가
    따라오는지 확인한다.
  * 메뉴 줄에 창을 끄는 영역이 등록돼 있는지 확인한다.

#### FR-22. 메뉴 줄과 상태 표시줄

* 내용: 메뉴 줄은 `File` · `View` · `Help` 세 벌로 시작한다. 메뉴 바깥을 누르면 열린
  메뉴가 닫힌다. 상태 표시줄은 왼쪽에 선택 영역별 활성 대상을, 오른쪽에 프로그램
  이름 · 버전 · 빌드일자 · 갈래 이름을 표시한다. 세로 띠 아래쪽에서 상태 표시줄을
  접고 펼 수 있다.
* 근거: D-11, v0.1 FR-3 · FR-4 · FR-23
* 판정 방법:
  * 세 메뉴가 열리고, 바깥을 누르면 닫히는지 확인한다.
  * 팝오버가 자신이 속한 메뉴 버튼의 왼쪽 끝에 맞춰 열리는지, 메뉴마다 서로 다른
    자리에서 열리는지 확인한다.
  * 상태 표시줄 오른쪽에 네 값이 모두 있는지 확인한다.
  * 세로 띠의 토글로 상태 표시줄이 접히고 펴지는지 확인한다.

#### FR-23. 미리보기 탭과 고정 탭

* 내용: 트리에서 한 번 고르면 미리보기 탭으로 열리고, 두 번 고르면 고정된다. 미리보기
  탭은 패널마다 하나뿐이며, 다른 대상을 미리보기로 열면 그 자리를 대신한다. 미리보기
  탭에서 `Enter`를 다시 누르면 고정된다.
* 근거: D-11, v0.1 FR-13 · D-13
* 판정 방법:
  * 한 번 고른 뒤 다른 것을 한 번 골라 탭 수가 1로 유지되는지 확인한다.
  * 두 번 고른 뒤 다른 것을 한 번 골라 탭 수가 2가 되는지 확인한다.
  * 미리보기 탭에서 `Enter`를 반복해 눌렀을 때 고정되는지 확인한다.
  * 위 셋을 FR-9로 연 탭에 대해서도 확인한다.

#### FR-24. 보기 영역 가르기와 탭 이동

* 내용: 보기 영역을 좌우 둘로 가를 수 있어야 한다. 가른 상태에서 초점이 있는 조각이
  시각적으로 구분돼야 하고, 탭을 반대쪽 조각으로 옮길 수 있어야 한다. 조각의 탭이
  모두 닫히면 가르기가 풀린다.
* 근거: D-11, v0.1 FR-14 · D-12
* 판정 방법:
  * 가르기 뒤 조각이 둘이 되고, 초점 조각이 표시되는지 확인한다.
  * 탭을 반대쪽으로 옮겼을 때 그 탭의 보기 인스턴스가 유지되는지 확인한다(FR-12).
  * 한쪽 조각의 탭을 모두 닫았을 때 가르기가 풀리는지 확인한다.
  * 셋 이상으로 가를 수 없는지 확인한다.

#### FR-25. 최소 조합키 집합

* 내용: 다음 열한 가지만 예약하고, 그 밖의 조합키를 예약하지 않는다.
  `F11`(Zen 토글) · `Esc`(메뉴 닫기, 없으면 Zen 해제) · `Ctrl+O`(폴더 열기) ·
  `Ctrl+W`(활성 탭 닫기) · `Ctrl+B`(탐색기 접고 펴기) · `Ctrl+\`(보기 영역 가르기) ·
  `F5`(새로 읽기) · `Alt+F4`(창 닫기) · `Tab`/`Shift+Tab`(초점 영역 순환) ·
  `Ctrl+Tab`/`Ctrl+Shift+Tab`(조각 안 탭 넘기기)
* 근거: D-11, v0.1 FR-10a · D-6
* 판정 방법:
  * 열한 가지가 대응 메뉴 · 버튼과 같은 결과를 내는지 각각 확인한다.
  * 갈리지 않은 상태에서 `Tab` 두 번, 가른 상태에서 세 번에 탐색기로 돌아오는지
    확인한다.
  * 위 목록 밖의 `Ctrl` · `Alt` 조합키에 껍데기가 반응하지 않고 보기에 그대로
    전달되는지 확인한다.
  * 껍데기가 예약한 조합키 수가 열한 개인지 확인한다.

#### FR-26. 설정 보존

* 내용: 보존하는 것은 껍데기의 화면 상태와 마지막 루트 · Recent Folders뿐이며, 실행
  파일 옆 한 파일에 담는다. **열린 탭 목록과 보기의 세션 상태는 보존하지 않는다**
  (FR-13). 설정 파일이 망가졌으면 기본값으로 떨어지고 앱은 계속 떠야 한다. 설정에는
  판 번호가 있어야 한다.
* 근거: D-5, v0.1 FR-27 · D-19
* 판정 방법:
  * 테마 · 아이콘 테마 · 탐색기 폭 · 상태 표시줄 표시 여부가 다시 켠 뒤 유지되는지
    확인한다.
  * 열린 탭이 다시 켠 뒤 0개인지 확인한다.
  * 망가진 설정 파일로 앱이 기본값으로 뜨는지 확인한다.
  * Recent Folders 지우기가 다른 설정을 건드리지 않는지 확인한다.

#### FR-27. CLI 인자로 대상 받아 시작

* 내용: 실행 파일이 CLI 인자로 루트 폴더 경로를 받아 그 루트로 시작할 수 있어야 한다.
  또한 갈아끼우는 자리(FR-9)를 통해, 시작 시 받은 인자로 탭을 여는 것이 껍데기 코드
  수정 없이 가능해야 한다.
* 근거: D-3, `BRIEF.md` 5절 4번, v0.1 FR-31
* 판정 방법:
  * 루트 경로를 인자로 넘겨 실행했을 때 그 루트로 트리가 뜨는지 확인한다.
  * 없는 경로 · 파일 경로를 넘겼을 때 기본 동작으로 떨어지고 앱이 뜨는지 확인한다.
  * 파일 경로를 인자로 받아 그 탭을 열고 시작하는 시험에서, 껍데기 코드의 변경 줄
    수가 0인지 확인한다.

### 1.7 프리셋 · 두 갈래 · 경계

#### FR-32. 프리셋 둘

* 내용: 파일 프리셋과 폴더 프리셋을 템플릿 안에 함께 넣는다. 각 프리셋은 갈아끼우는
  자리 다섯 중 셋(트리 항목 · 행 선택 매핑 · 중복 정책)을 미리 채워 둔다. 복사한 직후
  프리셋 하나를 고르면 바로 동작해야 한다.

  | 프리셋 | 트리 항목 | 행 선택 매핑 | 중복 정책 |
  | --- | --- | --- | --- |
  | 파일 | 파일과 폴더 | 파일 행 → 파일 탭 | 조각 안에서 판정 |
  | 폴더 | 폴더만 | 폴더 행 → 폴더 탭 | 패널 안에서 판정 |

  프리셋은 복사 직후 바로 동작하는 예시이지 모든 앱의 최대공약수가 아니다. 같은
  폴더에서 여러 세션을 여는 것처럼 다른 값이 필요한 앱은 프리셋을 고치지 않고 중복
  정책 자리(FR-8)를 갈아끼운다(D-14).

* 판정 방법:
  * 각 프리셋을 고른 상태에서 트리 표시와 행 선택 결과가 위 표와 같은지 확인한다.
  * 두 프리셋이 갈아끼우는 자리 밖의 껍데기 코드를 각자 갖고 있지 않은지 확인한다.
  * 프리셋을 바꿀 때 껍데기 코드의 변경 줄 수가 0인지 확인한다.

## 3. 제약사항

1. **실행 환경** — pywebview 갈래와 Electron 갈래 둘을 쓴다(D-8). 이 둘 외의 실행
   환경을 추가하지 않는다.
2. **렌더링 계열** — 두 갈래 모두 Chromium 계열 엔진 위에서 화면을 그린다. 껍데기와
   디자인 파일을 한 벌로 공유하는 전제이므로 이를 깨지 않는다.
3. **빌드 없는 소재** — 껍데기 · 프리셋 · 디자인 파일은 빌드 단계 없이 두 호스트가
   그대로 로드하는 소재로 쓴다(D-13). 번들러 · 트랜스파일러 · 프레임워크를 템플릿에
   넣지 않으며, 저장소에 빌드 산출물을 만드는 단계가 0건이다. 프레임워크가 필요한
   앱은 보기 안에서 자기 것을 고르고, 필요한 빌드도 자기 쪽에 둔다.
4. **대상 플랫폼** — Windows 로컬 실행을 1차 대상으로 한다.
5. **껍데기의 종류 무지** — 껍데기 코드는 리소스 종류를 알지 못한다(FR-4). 종류를 아는
   코드는 갈아끼우는 자리 안에만 둔다.
6. **껍데기의 실행 환경 무지** — 껍데기 코드는 실행 환경의 이름과 API를 알지 못한다
   (FR-35). 실행 환경에 닿는 코드는 각 갈래의 연결 계층에만 둔다.
7. **디자인 값의 출처** — 색 · 글꼴 · 간격 · 치수는 v0.1에서 옮겨 적은 값을 쓰고, 이번
   버전에서 새로 정하지 않는다(D-10, FR-28).
8. **도메인 로직 없음** — 마크다운 렌더링 · 신호 분석 · 파일 관리 · 터미널 실행 코드를
   담지 않는다. 참조 보기는 FR-33의 범위를 넘지 않는다.
9. **코드 생성기 없음** — 자동 생성 마법사나 전용 명령 도구를 만들지 않는다. 복제와
   교체는 사람이 문서를 보고 직접 한다.
10. **복제 단위** — 배포 단위는 프로젝트 전체다. 설치형 라이브러리나 패키지로 만들지
    않는다(D-2).
11. **문서 규약** — `project-workflow`의 `DOC-SCHEMA.md`와 `INIT.md`를 따른다. 판정은
    FR-38이 담당한다.

## 4. 미구현 대상

이번 버전에서 하지 않는 것. `BRIEF.md` 3절이 범위를 말하고 여기는 항목을 말한다.

1. **네 앱** — 마크다운 뷰어 · FFT analyzer · 폴더 간 파일 관리 툴 · 멀티터미널 중
   어느 것도 만들지 않는다. 이번에 만드는 것은 그것들이 꽂힐 자리다.
2. **도메인 기능** — 마크다운 렌더링 · FFT 분석 · 파일 복사와 이동과 삭제와 이름
   변경 · 터미널 프로세스 실행을 구현하지 않는다.
   * **터미널 요구의 실증도 하지 않는다** — 같은 폴더에서 여러 세션을 여는 것,
     장기 실행 프로세스를 보기가 안고 있는 것을 실제 프로세스로 확인하지 않는다.
     자리를 열어 두는 것까지가 범위이고, 검증은 템플릿 → 폴더 탐색기 → 멀티터미널
     순서에서 한다(D-14). 자리 자체는 FR-2 · FR-8 · FR-12가 시험용 보기로 판정한다.
3. **계열 레이어** — 템플릿과 앱 사이에 파일 계열 · 폴더 계열 중간 템플릿을 두지
   않는다. 계열은 프리셋으로만 존재한다(D-7).
4. **디자인 자산의 분리** — `shared/design`을 별도 저장소나 패키지로 떼어내지 않는다.
   경로와 의존 방향만 나중에 뗄 수 있게 잡아 둔다(D-9).
5. **시각 체계 재설계** — 색 · 글꼴 · 간격 · 아이콘을 이번 버전에서 새로 정하지
   않는다(D-10).
6. **열린 탭 복원** — 열린 탭 목록과 보기의 세션 상태를 설정에 저장해 다시 켤 때
   복원하지 않는다(D-5, FR-26).
7. **Dashboard 원형** — 요약 지표와 목록 표 위주의 UI는 다루지 않는다. 별도 프로젝트의
   몫이다.
8. **탭 오버플로 이동 수단** — 폭을 넘쳐 밀린 탭을 목록으로 보여주는 수단을 만들지
   않는다. `Ctrl+Tab`이 일부 완화한다.
9. **탭 끌어 순서 바꾸기** — 탭을 끌어 재배치하는 기능을 만들지 않는다.
10. **세 조각 이상 가르기** — 보기 영역을 셋 이상으로 가르지 않는다.
11. **파일시스템 변경 자동 감지** — 대상이 바뀌는 것을 감시해 트리에 자동 반영하지
    않는다. 새로 읽기로만 갱신한다.
12. **모바일과 클라우드 배포** — 다루지 않는다.
13. **설치 프로그램과 배포 검증** — 실행 파일 묶음과 clean 환경 설치 검증을 하지
    않는다. **CLI 인자로 루트를 받는 것은 이 배제 대상이 아니다** — 진입점 로직이며
    FR-27이 정의한다.
